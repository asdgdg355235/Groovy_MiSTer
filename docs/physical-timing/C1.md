# C1: Q25 critical MLAB even-bank read-address factoring

* Exact control source: `3b8d1edb63f2d2fed05d23323c3ba1ae93eeed1a`
* Compiler: Quartus Prime Lite 25.1std.0 Build 1129
* FPGA: `5CSEBA6U23I7`
* Source delta: `rtl/CRT/crt_vsize_fixed.sv` only.
* No pin, clock, PLL, seed, constraints, RAM mode, or physical assignment changes.

The slow 100C R0 setup failure launches at `emu|vga|hb` and captures at
`crt_vsize_fixed:u_vsize|packed_ram[1].even_ram|...dataout_reg[2]`.
The reported timing deficit is 0.077 ns. The fitted path has 2.590 ns
cell delay and 8.892 ns routing delay. A second setup violation reaches
a bank-1 even MLAB mux from a generated `advance_rows[0]` node.

`LINE_PX=2560` and `GROUP_PX=5` give `LINE_WORDS=512`, so
`address_word(slot, word)` is the concatenation of a 3-bit slot
base and a 9-bit word offset for this 3072-word bank.
The original bank-1 even read input selected a full 12-bit address
between line-start and current-column addresses. C1 selects the
3 high slot bits and gates the 9 low word-offset bits independently.
Other banks, geometry configurations, and all registers retain the
original implementation. The six synchronous RAMs are unchanged.

The source-to-physical correspondence identifies the bank-1 even RAM
read port and hb launch. It does not prove that the new logic will
place closer to the MLABs or improve fitted slack; that must be measured.

Control hardware manifest `tests/physical/hardware_q25.json` is retained.
The one allowed hash substitution is in
`tests/physical/q25_targeted_experiment.json`.
Non-Quartus checks compare all six RAM addresses, writes, data,
read data, RGB and control cycles against the historic baseline via
`tests/run_crt_read_address_rtl.py` plus the new exhaustive
slot/word/line-start address identity test. Full Quartus inference
and routing remain unverified.
